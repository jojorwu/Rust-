# Архитектура проекта Pumpkin

Pumpkin — это реализация сервера Minecraft с открытым исходным кодом, написанная с нуля на языке Rust. Сервер спроектирован для обеспечения высокой производительности, многопоточной масштабируемости и строгого соответствия сетевому протоколу Vanilla Java Edition, а также предоставляет современный API для плагинов на Rust и WebAssembly (Wasm).

---

## 1. Основные архитектурные принципы

Pumpkin использует гибридную модель параллелизма, которая разделяет детерминированную игровую логику и высокопроизводительную обработку ввода-вывода/сетевых пакетов:

1. **Асинхронная сеть и ввод-вывод (Tokio)**: Все сетевые сокеты, кодирование и декодирование пакетов, обращение к диску, протоколы RCON/Query и асинхронные события плагинов работают на базе асинхронной среды исполнения Tokio.
2. **Синхронный игровой такт (Tick Loop)**: Обновление ключевого игрового состояния — передвижение сущностей, тики блоков, операции с инвентарем и расчет урона — выполняется синхронно в главном цикле (20 тиков в секунду, интервал 50 мс). Это гарантирует строгий детерминизм и исключает блокировки (lock contention).
3. **Параллельные вычисления (Rayon)**: Ресурсоемкие задачи, не требующие мгновенного доступа к синхронному состоянию игры (генерация ландшафта чанков, расчет освещения, пакетная сериализация), передаются в пул потоков Rayon.
4. **Авторитетность клиента при перемещении (Client-Authoritative Movement)**: В отличие от официального сервера Vanilla Java, где движение игрока симулируется сервером, Pumpkin доверяет перемещению клиента с серверной валидацией для снижения задержек и рывков.

## 2. Обзор структуры Workspace (Крейты)

Код проекта организован как Cargo Workspace, состоящий из специализированных крейтов:

```
crates/
├── pumpkin/                 # Точка входа исполнимого файла и CLI сервера
├── pumpkin-core/            # Ядро сервера, игровое состояние, цикл тиков, сущности
├── pumpkin-protocol/        # Сетевой протокол Minecraft, кодеки и структуры пакетов
├── pumpkin-world/           # Загрузка/сохранение чанков, генерация мира, освещение, регионы
├── pumpkin-data/            # Сгенерированные статические данные (блоки, предметы, сущности)
├── pumpkin-command/         # Диспетчер команд, парсинг AST, аргументы команд
├── pumpkin-inventory/       # Окна контейнеров, инвентарь игрока, предмета и рецепты
├── pumpkin-nbt/             # Парсер и сериализатор формата NBT (Named Binary Tag)
├── pumpkin-config/          # Загрузка и структуры конфигурации TOML
├── pumpkin-auth/            # Аутентификация сессий Mojang и шифрование online-mode
├── pumpkin-scheduler/       # Планировщик синхронных и асинхронных задач
├── pumpkin-gametest/        # Внутренние интеграционные тесты игровой механики
├── pumpkin-plugin-api/      # Публичный Rust SDK для разработки плагинов
├── pumpkin-plugin-runtime/  # Управление жизненным циклом плагинов
├── pumpkin-plugin-utils/    # Вспомогательные макросы и утилиты для плагинов
├── pumpkin-plugin-wit/      # Определения интерфейсов WebAssembly (WIT)
├── pumpkin-wasm-host/       # Интеграция хоста Wasmtime runtime
├── pumpkin-wasm-host-v0_1/  # Реализация хоста Wasm для API v0.1
├── pumpkin-wasm-host-v0_2/  # Реализация хоста Wasm для API v0.2
├── pumpkin-wasm-host-common/# Общие трейты и абстракции для Wasm-хостов
├── pumpkin-util/            # Вспомогательные математические и пространственные структуры
├── pumpkin-codecs/          # Утилиты бинарной сериализации
├── pumpkin-macros/          # Процедурные макросы для внутренней регистрации
└── pumpkin-api-macros/      # Процедурные макросы для генерирования Plugin API
```

## 3. Детальное описание подсистем

### 3.1 Сетевой стек и протокол (`pumpkin-protocol` и `pumpkin-core`)

Сетевая подсистема преобразует необработанный байтовый поток TCP/UDP в структурированные типы данных Rust:

- **Машина состояний**: Соединение проходит через четко определенные фазы:
  `Handshake` ➔ `Status` / `Login` ➔ `Configuration` ➔ `Play`.
- **Формат пакета**: Каждый пакет состоит из префикса длины (VarInt), ID пакета (VarInt) и полезной нагрузки (payload).
- **Шифрование и сжатие**:
  - На этапе `Login` может включаться потоковое шифрование AES-CFB8 через обмен ключами RSA (`pumpkin-auth`).
  - При превышении порогового размера пакета динамически подключается сжатие zlib/flate2.
- **Сессия игрока**: Для каждого подключенного игрока в Tokio запускается сетевая задача, обрабатывающая входящие пакеты и передающая команды в объект сессии игрока.

### 3.2 Управление миром и чанками (`pumpkin-world`)

Движок мира отвечает за пространственное отслеживание, загрузку, генерацию и сохранение чанков:

- **Форматы чанков**:
  - **Anvil (`.mca`)**: Совместимость со стандартным форматом регионов Minecraft.
  - **Linear Format**: Высокопроизводительный сжатый формат регионов.
  - **Pump Format**: Собственный оптимизированный формат Pumpkin.
- **Движок освещения**: Алгоритмы расчета небесного (sky light) и блочного (block light) света выполняются параллельно на потоках Rayon.
- **Палитры секций**: Состояния блоков внутри секций чанка хранятся с использованием сжатых палитр с битовой упаковкой для минимизации расхода памяти.

### 3.3 Синхронизация и цикл тика (Tick Loop)

Сервер работает с фиксированной частотой 20 тиков в секунду (50 мс на тик):

1. **Фаза Pre-Tick**: Сбор входящих сетевых пакетов и межпоточных событий.
2. **Запланированные задачи**: Выполнение асинхронных и синхронных задач планировщика `pumpkin-scheduler`.
3. **Тики мира и сущностей**: Обновление тиков блоков, растекание жидкостей, выполнение ИИ мобов и обновление позиций сущностей.
4. **Фаза Post-Tick**: Рассылка изменений состояния (перемещение сущностей, блоки, таб-лист) игрокам в зоне видимости.
5. **Синхронизация**: Ожидание окончания 50-миллисекундного интервала. При превышении времени в лог выводится предупреждение.

### 3.4 Архитектура сущностей и ИИ (`pumpkin-core`)

- **Иерархия сущностей**: Базовые свойства (`EntityBase`) общие для всех сущностей. Специализированное поведение (мобы, предметы, снаряды) накладывается через специализированные структуры и трейты.
- **Целевая система ИИ (Goal AI)**: Мобы выполняют поведение через приоритетный диспетчер целей (трейт `Goal`), соответствующий механикам ванильной игры (поиск пути, выбор цели, атака).
- **Пространственный трекинг**: Видимость сущностей и их обновления отслеживаются по чанкам, чтобы отправлять пакеты только игрокам, находящимся в радиусе видимости.

### 3.5 Подсистема плагинов (`pumpkin-plugin-*` и `pumpkin-wasm-host*`)

Pumpkin поддерживает две модели выполнения плагинов:

- **Нативные Rust-плагины**: Компилируются напрямую вместе с сервером, обеспечивая максимальную производительность без накладных расходов.
- **WebAssembly (Wasm) плагины**:
  - Безопасная песочница на базе `wasmtime` (Component Model).
  - Интерфейсы взаимодействия описаны с помощью WIT (`pumpkin-plugin-wit`).
  - Плагин в Wasm не может обрушить основной процесс сервера.

### 3.6 Генерация данных (`pumpkin-data` и `tools/pumpkin-codegen`)

Статические данные Minecraft (ID блоков, состояния, свойства предметов, теги) не прописываются вручную:

1. Данные извлекаются из официального клиента/сервера с помощью инструмента [Extractor](https://github.com/Pumpkin-MC/Extractor) и сохраняются в формате JSON в папке `assets/`.
2. Утилита `tools/pumpkin-codegen` во время сборки обрабатывает эти данные и генерирует строгой типизации Rust-код в `crates/pumpkin-data/src/generated/`.
3. Ручной код сервера использует константы из `pumpkin-data`.

## 4. Безопасность и производительность

- **Правила блокировок**: В асинхронном контексте Tokio запрещено удерживать мьютексы и guard-объекты `DashMap` через точки `.await`.
- **Соответствие Vanilla**: Все математические формулы, последовательности пакетов и порядок событий проверяются по декомпилированному исходному коду Java.
- **Качество кода**: Настройки Clippy запрещают `unwrap`, `expect` и `panic` в основном runtime коде сервера. Ошибки обрабатываются через `Result`/`Option` и логируются через `tracing`.
